# 오행전기 · 음양오행 턴제 배틀

태어난 순간의 **사주팔자(음양오행)** 로 주인공의 능력치가 정해지고, 가챠로 모은 동료와 4인 파티를 꾸려
1~10명의 랜덤 적과 싸우는 웹 턴제 RPG. 모바일 세로 화면 기준, 서버 없이 브라우저에 저장됩니다.

```bash
npm install
npm run dev        # 개발 서버
npm test           # 엔진 단위 테스트
npm run balance    # 적 수(1~10) × 난이도별 승률 시뮬레이션
npm run build      # 타입체크 + 빌드 (dist/)
```

`main` 브랜치에 푸시하면 GitHub Actions가 테스트 → 빌드 → GitHub Pages 배포를 합니다
(저장소 Settings → Pages → Source 를 **GitHub Actions** 로 설정).

## 게임 규칙

### 주인공 = 사주팔자
생년월일시(양력)로 년·월·일·시주 8글자를 계산합니다 (`src/engine/saju.ts`).
- 년주는 입춘(2/4), 월주는 절기 경계(근사) 기준, 일주는 60갑자 일수 계산, 시주는 2시간 단위
- 8글자의 오행 개수 → 능력치, **일간(日干)** 의 오행/음양 → 주인공의 속성
- 시간을 모르면 6글자를 8글자 비율로 환산

| 오행 | 담당 능력치 |
|---|---|
| 木 목 | 속도 |
| 火 화 | 공격 |
| 土 토 | 체력 |
| 金 금 | 방어 |
| 水 수 | 기(氣) — 회복량, 상태이상 확률, 기력 회복 |

양(陽)은 공격·속도 +10%, 음(陰)은 방어·기 +10%.
주인공은 **사주에 있는 오행의 스킬만** 배울 수 있고, 레벨에 따라 해금되며 4개까지 장착합니다.

### 상성
- 상극(木→土→水→火→金→木): 공격 오행이 상대를 극하면 **×1.5**, 반대로 극당하면 **×0.67**
- 상생(木→火→土→金→水→木): 상대를 생해 주면 **×0.8**
- 음양이 반대면 ×1.1, 스킬 오행 = 시전자 오행이면 ×1.2

### 전투
- 아군 4명(주인공 고정) vs 적 1~10명이 모두 필드에 나오는 다수 전투
- 라운드마다 아군 각자의 스킬·대상을 고르면 모든 유닛이 속도순으로 행동
- 기력(MP) 100, 라운드마다 회복. 기본 공격은 기력 0
- 적은 적을수록 개체가 강하고(1명 = 두목), 많을수록 약함
- 자동 전투 / 2배속 지원. 승리 시 영석 💠 + 경험치, 패배 시 경험치 30%

### 소환(가챠)
- 1회 160 / 10회 1600 영석, N 60% · R 30% · SR 8.5% · SSR 1.5%
- 80회째 SSR 확정(천장), 10연 R 이상 1장 보장, 픽업 캐릭터
- 중복은 성급 ★+1 (최대 ★5, ★당 능력치 +5%)

## 콘텐츠 추가 (캐릭터 · 스킬 · 적 · 가챠)

모든 콘텐츠는 `data/*.json` 에 있고, 빌드·테스트 시 Zod 스키마와 참조 무결성(없는 스킬 id 등)을 검사합니다.

| 파일 | 내용 |
|---|---|
| `data/characters.json` | 가챠 캐릭터 (오행, 음양, 등급, 능력치 성향, 스킬 4개) |
| `data/skills.json` | 스킬 (오행, 공격/회복/보조, 대상, 위력, 기력, 상태이상/버프, 주인공 습득 레벨) |
| `data/enemies.json` | 적 템플릿, 오행별 이름 접두어, 적 수(1~10) 출현 가중치 |
| `data/gacha.json` | 비용, 등급 확률, 천장, 10연 보장, 픽업, 시작 영석 |

### 방법 1 — 어드민 페이지 (권장)
1. `/#/admin` 접속 (비밀번호: 환경변수 `VITE_ADMIN_PASS`, 기본값 `ohaeng`)
2. 캐릭터/스킬/적/가챠 탭에서 폼으로 추가·수정 — 능력치 미리보기, 상성표, 샘플 적 생성, 가챠 1만회 시뮬
3. **시뮬레이터** 탭에서 적 수별 승률 확인
4. "게임에 적용"을 켜면 *이 브라우저에서만* 드래프트로 실제 플레이 테스트
5. **내보내기** 탭에서 JSON을 다운로드 → `data/` 파일 교체 → 커밋 & 푸시 → 모든 유저에게 배포

> 정적 사이트라 어드민 비밀번호는 일반 유저가 실수로 들어오지 않게 하는 정도입니다.
> 어드민에서 바꾼 내용은 JSON을 커밋하기 전까지 다른 유저에게 영향을 주지 않습니다.

### 방법 2 — JSON 직접 편집
`data/characters.json` 에 항목을 추가하고 `npm test` 로 검증합니다.

```json
{
  "id": "moon_rabbit",
  "name": "달토끼",
  "emoji": "🐇",
  "element": "water",
  "polarity": "yin",
  "rarity": "SR",
  "profile": { "hp": 1.0, "atk": 0.9, "def": 0.9, "spd": 1.3, "qi": 1.2 },
  "skills": ["water_heal", "water_ice", "wood_breeze"],
  "description": "달에서 내려온 토끼"
}
```

`id` 는 세이브 데이터의 키이므로 배포 후에는 바꾸지 마세요.
